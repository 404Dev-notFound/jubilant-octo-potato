4. AUTHENTICATION & JWT SE CURRENT USER KAISE IDENTIFY HOTA HAI
--------------------------------------------------------------------------------
1. Jab user login/signup karta hai, backend Express server JWT token generate karke client ko bhejta hai.
2. Client is token ko user object ke sath `localStorage.setItem('currentUser', JSON.stringify(user))` me store kar leta hai.
3. Jab bhi frontend se `window.apiFetch(endpoint, options)` call hota hai:
   - `apiFetch` check karta hai agar `localStorage.getItem('currentUser')` exist karta hai.
   - Wo user object parse karta hai aur `currentUser.token` nikalta hai.
   - Request headers me inject kar deta hai:
     `headers['Authorization'] = 'Bearer ' + currentUser.token;`
4. Jab request Express server par aati hai, to route se pehle `authMiddleware` run hota hai:
   - `req.headers['authorization']` se Bearer token extract karta hai.
   - `jwt.verify(token, JWT_SECRET, (err, decoded) => ...)` se token ko verify karta hai.
   - Decoded payload me user ki details hoti hain: `{ id: "...", email: "...", role: "..." }`.
   - Middleware is decoded data ko `req.user = decoded;` par attach kar deta hai aur `next()` call karta hai.

--------------------------------------------------------------------------------
5. `creatorId` AUTHENTICATED USER KE SATH KAISE SECURELY BIND HOTI HAI
--------------------------------------------------------------------------------
- Frontend se client koi bhi `creatorId` nahi bhejta (security risk se bachne ke liye).
- Backend Express handler `app.post('/api/projects/:projectId/issues')` ke andar:
  `const creatorId = req.user.id;`
- Ye `req.user.id` direct verified JWT token se aati hai jo spoof nahi ho sakti.
- Is tarah issue create karne wale user ki sahi ID hamesha record ke sath associate hoti hai.

6. REQUEST EXPRESS TAK KAISE PAHUNCHTI HAI
--------------------------------------------------------------------------------
1. `window.handleAddIssue` function me:
   ```javascript
   const res = await window.apiFetch(`/api/projects/${projectId}/issues`, {
       method: 'POST',
       body: JSON.stringify(payload)
   });
   ```
2. Browser HTTP POST request bhejta hai `http://localhost:3000/api/projects/:projectId/issues` par.
3. Express server me pehle global middlewares (`cors()`, `express.json()`) parse karte hain.
4. Route middleware `authMiddleware` JWT authenticate karta hai.
5. Fir request route handler ke andar aati hai jahan `req.params.projectId` aur `req.body` ka data milta hai.

7. PRISMA ISSUE RECORD KAISE BANATA HAI
--------------------------------------------------------------------------------
1. Server check karta hai ki kya project exist karta hai:
   `const project = await prisma.project.findUnique({ where: { id: projectId } });`
2. Enums aur input sanitize karne ke baad Prisma ORM ka `create` method execute hota hai:
   ```javascript
   const issue = await prisma.issue.create({
       data: {
           title: title.trim(),
           description: description ? description.trim() : '',
           status: issueStatus,     // 'TODO' | 'IN_PROGRESS' | 'DONE'
           priority: issuePriority, // 'LOW' | 'MEDIUM' | 'HIGH' | 'URGENT'
           tags: tagsArray,         // ['bug', 'frontend']
           assigneeId: assigneeId ? String(assigneeId).trim() : null,
           creatorId: req.user.id,
           projectId: projectId
       }
   });
   ```

8. POSTGRESQL ME DATA KAISE STORE HOTA HAI
--------------------------------------------------------------------------------
1. Prisma internally SQL query generate karta hai:
   `INSERT INTO "Issue" ("id", "title", "description", "status", "priority", "tags", "creatorId", "assigneeId", "projectId", "createdAt", "updatedAt") VALUES (gen_random_uuid(), ...);`
2. PostgreSQL database me:
   - `id`: Unique UUID primary key banti hai.
   - `status`: Enum type `IssueStatus` ke mutabiq validate hoti hai.
   - `priority`: Enum type `IssuePriority` ke mutabiq validate hoti hai.
   - `tags`: PostgreSQL TEXT[] array column me store hoti hai.
   - `projectId`: Foreign key relation se link hoti hai. Agar project delete ho to cascade delete rule se issue bhi delete ho jayega.
   - `createdAt` & `updatedAt`: Current timestamp par set hote hain.

11. PAGE RELOAD HONE KE BAAD DATA DATABASE SE KAISE FETCH HOTA HAI
--------------------------------------------------------------------------------
1. Jab page reload hota hai (e.g. URL `#issues?projectId=abc-123`), `js/app.js` ka router initialize hota hai.
2. Router `initIssues(projectId)` call karta hai `js/views/issues.js` me.
3. `initIssues()` function backend par authenticated GET request bhejta hai:
   `const res = await window.apiFetch('/api/projects/' + currentProjectId + '/issues');`
4. Express route `app.get('/api/projects/:projectId/issues')` Prisma query chalata hai:
   ```javascript
   const issues = await prisma.issue.findMany({
       where: { projectId: projectId },
       orderBy: { createdAt: 'asc' }
   });
   res.json(issues);
   ```
5. PostgreSQL se live rows fetch hokar array ke roop me aati hain.
6. Frontend ka `renderBoard(issues)` function issues ko loop karta hai aur cards bana kar unke respective columns (TODO, IN_PROGRESS, DONE) me append kar deta hai.

12. INVOLVED API ENDPOINTS LIST
--------------------------------------------------------------------------------
1. `POST /api/auth/login` & `POST /api/auth/signup`
   - Purpose: User authentication aur JWT access token issue karna.
2. `GET /api/users`
   - Purpose: Assignee dropdown ke liye sanitized users list lana.
3. `GET /api/projects`
   - Purpose: Project switcher dropdown populate karna.
4. `GET /api/projects/:projectId/issues`
   - Method: GET (Protected - requires Bearer JWT)
   - Purpose: Ek specific project ke saare issues database se fetch karna.
5. `POST /api/projects/:projectId/issues`
   - Method: POST (Protected - requires Bearer JWT)
   - Body: `{ title, description, status, priority, tags, assigneeId }`
   - Purpose: Project ke andar naya issue create karna.
6. `PATCH /api/projects/:projectId/issues/:issueId`
   - Method: PATCH (Protected - requires Bearer JWT)
   - Body: `{ status, priority, description, assigneeId, tags, title }`
   - Purpose: Drag & drop ya manual move se status/priority update karna.
7. `DELETE /api/projects/:projectId/issues/:issueId`
   - Method: DELETE (Protected - requires Bearer JWT)
   - Purpose: Issue ko database se delete karna.
